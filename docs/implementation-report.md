## 3. Test outcomes (real, this tree)

**119 passed, 6 skipped** (`pytest tests/`, 8.2 s). The 6 skips are the Docker
sandbox-hardening probes (`tests/security/test_sandbox_security.py::TestSandboxHardening`),
each carrying reason `BLOCKED: 'docker' binary not found on PATH` — they are
NOT_RUN, not silently dropped.

Coverage highlights by acceptance area:

- Endpoint policy: 20+ cases incl. DNS-bypass monkeypatch and redirect escapes.
- Suite validation: duplicate IDs, missing files/manifests, extra dirs, broken
  YAML, traversal, symlink escapes, tamper→content-hash change, private-test
  verbatim leak, normalized duplicates.
- Statistics: Wilson vs an independent in-test implementation over 8 (k,n)
  pairs + literature reference values + exact 0/n, n/n limits + invalid inputs.
- Extraction/classification: fences, raw, empty; timeout/syntax/infra/malformed
  mapping; infrastructure vs model fault separation.
- Engine: full fixture lifecycle (24 cases, 18/24, verdict caps), tampered
  artifact detection, missing artifact detection, suite-tamper refusal,
  mid-run crash → FAILED → resume with preserved+flagged records, incomplete
  never PASS, sandbox refusal without Docker (host-execution trap asserted).
- API: health/suites/models/202+409/404s/422/pagination/report/verify/cancel.
- Local-only: socket-level guard asserting zero non-loopback connection
  attempts during a full run.

## 5. Known defects and limitations

1. **Docker hardening is unexecuted here** (Gate D) — the recipe and its
   verification are implemented and unit-refused, but adversarial probes need a
   daemon; treat sandbox guarantees as unproven until run.
2. **Black-box I/O checks** cannot enforce non-observable requirements
   (e.g. O(log n)); documented in methodology, one negative variant removed
   for exactly this reason during dev-side validation.
3. **Leakage scanning is heuristic** — verbatim/formatting-insensitive only;
   paraphrase and training-contamination detection out of scope.
4. **Single background worker** (sequential runs) — adequate for a local
   single-user tool; no distributed execution by design.
5. **Suite size (24)** — infrastructure verification, not capability statistics;
   CI width ~±0.16 at p≈0.75.
6. **Baseline runs in DB** — two early runs (INCOMPLETE/FAILED) from development
   remain in the demo database alongside the clean fixture run; they
   demonstrate crash recovery honestly and were preserved deliberately.
7. **`modelproof serve`** is the only tested server path; production WSGI
   deployment is explicitly out of scope.
