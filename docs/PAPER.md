## Abstract

Evaluation of coding language models has historically relied on authoritative scoreboards and unverifiable self-reported pass rates. Because benchmarks are evaluated in private, unverified harnesses, reported results are susceptible to prompt gaming, evaluation harness drift, silent timeouts, unprincipled denominator exclusion, and training data contamination. We present **ModelProof**, a local-first, evidence-first evaluation lab for coding models. Under ModelProof, an evaluation claim is invalid unless supported by an independently verifiable cryptographic evidence bundle. We formalize the **Claims Grammar**, define strict non-bypassable sandboxing criteria, and demonstrate that deterministic verification allows any third party to audit benchmark results in sub-second time without trusting the evaluator or re-running expensive inference.

---

## 1. Introduction

Evaluation leaderboards (e.g. HumanEval, MBPP, SWE-bench) form the foundation of current model ranking and selection. However, the evaluation pipeline presents severe epistemological limitations:
1. **Unverifiable Numbers:** A report stating *"Model X achieves 72.4% pass@1"* is an unprovable assertion. Reviewers cannot distinguish between genuine model completion, post-hoc prompt alterations, or silent infrastructure retries.
2. **Harness Leakage & Escape:** Execution of untrusted model code often lacks strict sandboxing, leading to file system tampering, network exfiltration, or environment contamination.
3. **Denominator Manipulation:** Infrastructure crashes, timeouts, and syntax errors are often silently filtered out from benchmark denominators, artificially inflating pass rates.

ModelProof replaces "trust-me" evaluation with verifiable cryptographic evidence.

## 2. The Claims Grammar

In ModelProof, an evaluation statement is expressed as a well-formed cryptographic predicate:

$$\mathcal{M} \models \text{pass}@k = p \pm \epsilon \quad \text{on } \mathcal{S} \text{ under } \mathcal{C} \text{ with evidence } \mathcal{E}$$

Where:
- $\mathcal{M}$: Verified model identity, bound by SHA-256 weight manifest digest $\mathcal{H}_M = \text{SHA256}(\text{Weights})$. Server-reported model IDs are treated strictly as unverified claims.
- $\mathcal{S}$: Suite specification, uniquely identified by immutable content digest $\mathcal{H}_S = \text{SHA256}(\text{Tasks} \cup \text{Private Checks})$.
- $\mathcal{C}$: Runtime configuration, defining timeouts ($t \le 10\text{s}$), memory caps ($256\text{MB}$), non-root execution (`65534:65534`), and network isolation (`--network none`).
- $p \pm \epsilon$: Estimated pass rate with Wilson 95% confidence interval $[\ell, u]$, computed over valid outcomes.
- $\mathcal{E}$: Evidence bundle, containing per-case outcomes, raw model outputs, stdout/stderr logs, and a SHA-256 manifest.

**Soundness Criterion:** A claim $\mathcal{M} \models \dots$ holds if and only if:
$$\text{Verify}(\mathcal{E}, \mathcal{H}_S, \mathcal{H}_C) = \text{PASS}$$

## 3. Sandboxing & Isolation Guarantees

Code generated by autonomous models is inherently untrusted. ModelProof establishes a strict defense-in-depth isolation boundary:
1. **Network Namespace Isolation:** Container network is set to `--network none`. No loopback proxy, no external egress.
2. **Read-Only Root Filesystem:** Root filesystem is mounted read-only (`--read-only`), preventing permanent environment mutation.
3. **Privilege Demotion:** Containers drop all Linux capabilities (`--cap-drop ALL`), set `--security-opt no-new-privileges`, and run as `nobody:nogroup` (`65534:65534`).
4. **Pre-Execution Runtime Inspection:** The runner inspects the container's effective `HostConfig` via the container daemon *prior* to starting execution. Any deviation raises `SandboxUnavailableError` and halts evaluation; silent fallback to host subprocesses is categorically prohibited.
5. **MicroVM Defense Option:** In high-risk environments, ModelProof integrates gVisor (`runsc`) to intercept system calls in userspace, mitigating shared-kernel escape vectors.

## 4. Denominator Invariance & Metric Reconciliation

Let $\mathcal{N}$ be the set of all tasks in suite $\mathcal{S}$. For each task $i \in \mathcal{N}$, the evaluation outcome $o_i$ belongs to:
$$\mathcal{O} = \{\text{PASSED}, \text{FAILED}, \text{TIMEOUT}, \text{INVALID\_OUTPUT}, \text{MODEL\_ERROR}, \text{SANDBOX\_ERROR}\}$$

The benchmark metric set is defined as:
- **Valid Model Outcomes (Denominator):**
  $$\mathcal{D} = \{ i \in \mathcal{N} \mid o_i \in \{\text{PASSED}, \text{FAILED}, \text{TIMEOUT}, \text{INVALID\_OUTPUT}, \text{MODEL\_ERROR}\} \}$$
- **Pass Rate:**
  $$\text{PassRate} = \frac{|\{ i \in \mathcal{N} \mid o_i = \text{PASSED} \}|}{|\mathcal{D}|}$$
- **Full-Suite Completion Rate:**
  $$\text{CompletionRate} = \frac{|\mathcal{D}| + |\{ i \in \mathcal{N} \mid o_i = \text{SANDBOX\_ERROR} \}|}{|\mathcal{N}|}$$

Under no circumstance may a model-attributable timeout or syntax failure be excluded from $\mathcal{D}$. If $|\mathcal{D}| < |\mathcal{N}|$ due to infrastructure errors, the evaluation gate assigns verdict `INCOMPLETE` or `INFRASTRUCTURE_FAIL`.

---

## 5. Verification Without Trust

To verify an evaluation run:
1. A verifier downloads the evidence bundle $\mathcal{E}$ (e.g. `tar.gz`).
2. Computes the SHA-256 digest of every case record and log file.
3. Compares all digests against `checksums.sha256`.
4. Recomputes pass rate, Wilson interval, and gate predicates independently.
5. In-browser client-side verification is executed via Web Crypto API in `< 500\text{ms}` with zero network calls and zero server trust.

---

## 6. Conclusion

ModelProof shifts LLM code evaluation from unverifiable self-reporting to transparent, reproducible, cryptographic proof. By coupling strict sandboxing with immutable evidence bundles, it provides the foundation for institution-grade benchmark science.
